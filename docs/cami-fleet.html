Models go to the device. The screen shows who is up.

Cami Fleet deploys an AI model to the machines you choose by label, verifies every byte against a SHA-256 fingerprint before it runs, and tracks each device by its own certificate. A 2.8-inch ESP32-S3 touch board joins the same fleet and lists the live agents — tap one to see exactly what its latest deployment required, and whether it qualified.

How a model travels

You choose the model and the labels. The control plane decides who qualifies. The device runs the file only after the hash matches. The display watches it all happen.

1

You choose

A model, a label like location = barcelona, and optional requirements: RAM, a CPU / GPU / NPU, or an architecture.

2

Targeting

Every matching device is recorded. One that lacks the RAM or the chip is skipped with the reason, not failed at load time.

3

The agent

The Rust agent downloads the file, keeps it only if the SHA-256 matches, and loads that exact file into LiteRT-LM, Ollama, or the stub.

4

The display

The ESP32 polls every 5 seconds. Each row shows the agent and its deployment; a tap shows what it needed and whether it has it.

The pieces

Agents speak gRPC. The display can't, so it uses the same identity checks over a smaller HTTPS API. Both dial out — neither needs an open port on the device.

Operator

Dashboard and API

The web app adds the API key on its own server, so the browser never holds it. Deployments can start as a canary percentage, then promote to everyone or roll back — rollback returns each device to the model it ran before.

Identity

The certificate is the name

Each device carries its own client certificate. The control plane reads the caller's name from that certificate, never from the request body, so one device cannot register or heartbeat as another.

On the device

Verified, then run

The agent hashes the download as it streams and discards the file if the digest differs; a cached file is re-hashed before each use. Inference happens on the device. “Ask a device” may first call three read-only tools: status, cached models, current model.

On the desk

Why the display is separate

The agent needs HTTP/2, protobuf, and TLS 1.3. This ESP32's TLS stack stops at TLS 1.2, and a screen gains nothing from a long-lived stream. Port 8443 runs the same register / heartbeat / ack / reconcile logic as JSON, and the board verifies the certificate name control-plane.

The ESP32 display

A diymore / LCDWIKI ESP32-S3 with a 240×320 ILI9341 screen and an FT6336 touch panel. It registers as esp32-display-1, heartbeats every 10 seconds, and is labeled type = esp32-display — only a device with that label receives the agent list (up to six members, running ones first).

The header counts how many agents are up. Each row is the agent's newest deployment and its status, or “nothing asked yet.”

A tap opens that agent: its architecture, RAM, accelerators, and the model it runs, then the three requirements — green when met, red when not — with the skip or failure sentence underneath.

To go back, tap anywhere on the detail screen, or press BOOT. BOOT can't choose a row.

Before it's online, the list is replaced by a status pill: amber while joining Wi-Fi or registering, red when the control plane doesn't answer. The RGB LED mirrors it — blue, green, red.

What the display will and won't do

It's a fleet member so you can watch the decisions on the desk — not an inference device. A model needs gigabytes of RAM; this board has 512 KB of on-chip SRAM.

It doesIt does not
✓Register under its certificate name and heartbeat like an agent ✕Run LiteRT-LM, Ollama, or any model
✓List who is up, and what the newest deployment required ✕Show artifact URLs, private keys, or another device's certificate
✓Report failed if a deployment targets the board, so the rollout isn't left waiting ✕Answer “Ask a device” — those tasks stay pending
✓Get skipped, with a reason, when a model needs more RAM, a GPU / NPU, or another architecture ✕Hold a deployment open
✓Go offline on the dashboard ~30 s after its last heartbeat ✕Stream token timings — there's nothing to measure
