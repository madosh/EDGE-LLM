Edge AI deployment · the complete guide

Ship a model to a fleet. Prove every byte that runs.

Cami Fleet deploys AI models to edge devices chosen by label. Each device checks the model's SHA-256 before running it, and each one is identified by its own certificate. You can stage a rollout, promote it or roll it back, and watch measured inference numbers come back. This page explains every part of the system and the role it plays, from the Go control plane to the Rust agents to the ESP32 touch screen on the desk.

01 · Overview

The system at a glance

Four layers. Operators work through the dashboard and REST API. The control plane decides which device gets which model, and keeps state in Postgres and telemetry in ClickHouse. Devices always dial out to it: Rust agents over gRPC, the ESP32 over HTTPS, both with mutual TLS. Setup jobs and observability run beside them.

03 · End to end

A deployment, step by step

You choose the model and the labels. The control plane decides who qualifies. Each device runs the file only after its hash matches, then reports measured numbers that the dashboard and the desk display show.

1

Choose

A model file and its SHA-256, a label selector like location=barcelona, an optional canary %, and requirements: RAM, CPU / GPU / NPU, architecture.

2

Target

Matching devices inside the rollout are recorded as pending and get the instruction pushed on their open stream. Those lacking a requirement are skipped, with the reason.

3

Verify and run

The agent reports downloading and verifying, checks the digest, loads that exact file, and reports running. A mismatch is reported as failed, and the old model keeps serving.

4

Measure and adjust

Probe telemetry flows into ClickHouse. You promote the canary, or roll back so each device returns to the model it ran before.

Devices: online from registration and each heartbeat (every 10 s); offline when the last heartbeat is more than 30 s old. A device that comes back reconnects by itself and is reconciled: it gets the newest deployment it should be running.
05 · Trust

Security model

The guarantees are: a device can act only as itself, it runs only bytes that match the published digest, and a lost device can be cut off within seconds.

Identity

The certificate is the name

Every device has its own client certificate, and its common name is the device name. The control plane reads the caller from the verified certificate, never from the request body, so one device cannot register, heartbeat or ack as another.

Integrity

Verified, then run

Artifacts are content-addressed by SHA-256 and re-hashed before every reuse. Runtimes get a file path or a digest, never "pull by name". A tampered file is refused in under a second, and the running model is untouched.

Revocation

Cut off in seconds

scripts/revoke-device.sh NAME adds the certificate's serial to revoked.txt. New handshakes fail at once, open streams close within 5 s, and the device shows offline about 30 s later. --undo lets it back in.

Operators

The key stays on the server

The REST API requires X-Api-Key. The dashboard's server adds it, so the browser never holds it. The ESP32 gets the fleet list only if labelled as a display, without artifact URLs or internal IDs.

06 · On the desk

The ESP32 display

A diymore ESP32-S3 with a 2.8" 240×320 ILI9341 screen and an FT6336 touch panel. It joins the fleet as esp32-display-1, labelled type=esp32-display, and turns the control plane's decisions into something you can see on the desk.

The list shows up to six agents, running ones first, each with its newest deployment and status. The header counts how many are up.

A tap opens an agent: architecture, RAM, accelerators, the model it runs, and its latest tokens/s and time to first token. These are green and "measured" from a real runtime, grey and "stub" when simulated. Below that are the three requirements, green when met and red when not, with any skip reason.

Going back: tap anywhere on the detail screen, or press BOOT.

Finding the PC: CP_ADDRESS can be pc-name.local. The firmware resolves it over mDNS and asks again after any failed connection, so a new DHCP address does not break it.

Before it is online, a status pill shows amber while joining Wi-Fi or registering, and red when the control plane does not answer. The RGB LED shows the same: blue, green or red.

09 · Why it is built this way

Design decisions and known limits

Each decision has a cost, and it is written down. Full records are in decisions.md; the debugging stories behind several of them are in field-notes.md.

Identity

Certificate, not request body

One certificate per device, so a stolen device can act only as itself. The cost: certificates must be issued per device and revoked when one is lost.

Integrity

Run the verified file

Digest-addressed artifacts, never pulled by name. The cost: a full download per device, with no layer sharing.

Targeting

Skips carry a reason

"Why didn't device X get it?" is answered in the data, which the dashboard and the desk display show. The cost: devices must report their capabilities truthfully.

Rollout

Stable hash buckets

The same answer on any instance, after any restart; promotion only adds devices. The cost: percentages are lumpy on small fleets.

Data

Postgres for state, ClickHouse for telemetry

Opposite shapes, each in the store that suits it. The cost: two databases, joined in Go.

Devices

HTTPS for microcontrollers, same trust

A second protocol is acceptable; a second trust model is not. The cost: the display polls instead of streaming.

Security

A watched revocation list

Checked at the handshake, per call and on open streams, and failing closed. The cost: a single control plane, and certificates are still long-lived.

Honesty

Simulated numbers are labelled

Every telemetry row says probe or stub, and the benchmark refuses stub data. When real inference arrived, nothing had to be relabelled.

Known limitWhat it means
One control-plane instanceLive streams are tracked in memory; a second instance would not see devices connected to the first.
Serial fan-outAbout 10.7 ms per device when a deployment is created. Batched inserts and concurrent pushes would fix it.
Revocation is a local listNo CRL or OCSP, and certificates last years. Short-lived certificates would be the real fix.
Small models skip toolsA 0.5B model answered without calling device_status. Next step: require tool evidence for status questions.
Telemetry is a probeThe numbers come from the agent's own short request, not from real user traffic.
Some endpoints are open/metrics and the event stream do not need the key; keep the control plane on a private network.
