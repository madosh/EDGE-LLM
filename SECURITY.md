# Security Policy

## Scope and intent

Cami Fleet is a **reference / demonstration project** for managing edge AI
deployments. It is not a hardened, production-ready product. Please read the
hardening notes below before exposing any part of it to an untrusted network.

## Reporting a vulnerability

Please **do not open a public issue for security vulnerabilities.**

Instead, report privately via GitHub's
[private vulnerability reporting](https://github.com/madosh/EDGE-LLM/security/advisories/new)
(Security → Report a vulnerability).

Please include:

- A description of the issue and why you believe it is a security problem
- Steps to reproduce, or a proof of concept
- The affected component (`control-plane`, `agent`, `web`) and commit

You can expect an initial acknowledgement within a reasonable effort basis.
This is a community project without a dedicated security team, so please set
expectations accordingly.

## Hardening notes — read before deploying

The defaults in this repository are tuned for a **local demo via Docker
Compose**, not for production. In particular:

| Area | Default | What to do for real use |
|------|---------|-------------------------|
| REST API key | `CAMI_API_KEY=changeme` | Set a strong, unique key. Never keep the default. |
| Postgres credentials | `cami` / `cami` (in `docker-compose.yml`) | Move to secrets, use a strong password, do not expose the port. |
| ClickHouse credentials | `cami` / `cami` (in `docker-compose.yml`) | Same as above. |
| Grafana admin | `admin` / `${GRAFANA_PASSWORD:-changeme}` | Set `GRAFANA_PASSWORD`; disable anonymous access. |
| mTLS certificates | Self-signed, generated by `scripts/gen-certs.sh` | Use a real CA and a proper certificate lifecycle with rotation. |
| Service ports | Bound for local access | Do not expose Postgres, ClickHouse, or NATS to the internet. |

These demo credentials are intentionally visible in `docker-compose.yml` so the
stack runs with one command. They grant access to nothing but a throwaway local
container.

## Secrets handling

- `.env` is git-ignored. Only `.env.example`, containing placeholders, is tracked.
- Generated TLS keys and certificates are git-ignored (see `.gitignore`).
- Model artifacts under `artifacts/` are generated at runtime and git-ignored.

If you believe a secret has been committed to this repository, please report it
privately using the process above rather than opening an issue.

## Design properties worth knowing

- **Artifact integrity** — deployments carry an expected SHA-256; the agent
  verifies downloaded bytes before loading and refuses on mismatch.
- **Device authentication** — device-to-control-plane gRPC uses mutual TLS.
- **API authentication** — the REST API requires `X-Api-Key` (or bearer auth).

These are real mechanisms, but they have not been independently audited. Treat
this project as a starting point, not a security guarantee.
